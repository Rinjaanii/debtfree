# DebtFree

Один сервис — два входа: **кто-то откроет в Telegram, кто-то в браузере**, а данные
у них одни и те же. Плюс автономный HTML-файл для тех, кому нужен вариант совсем без
сервера.

Долги, бюджет и стратегию каждый ведёт свои: вход подтверждается Telegram, поэтому
чужие данные недоступны ни через один запрос.

## Три способа пользоваться, один и тот же расчёт

| Способ | Кому подходит | Где данные |
|---|---|---|
| **Telegram Mini App** | удобнее всего на телефоне: открывается из чата с ботом одним нажатием | на сервере, по аккаунту Telegram |
| **Браузер** | с компьютера: удобно вводить много долгов и смотреть таблицы | те же, что в Telegram |
| **Файл `debtfree.html`** | нет сервера, нет интернета, нужно «просто посчитать» | в браузере, с экспортом в файл |

Все три считают на **одном и том же ядре** (`src/calc.js`), поэтому цифры не расходятся.
Правка в ядре или интерфейсе попадает во все формы сразу — автономный файл
пересобирается из тех же исходников.

## Посмотреть локально за минуту (без Telegram и без VPS)

Нужен только Node.js. В папке проекта:

```bash
node src/server.js --dev
```

Откройте <http://localhost:8080> — интерфейс сразу заработает. Флаг `--dev` включает
режим разработки: подпись Telegram не проверяется, вы входите автоматически как
тестовый пользователь «Разработчик», токен из `.env` при этом не трогается.

Что можно сделать в этом режиме: добавить долги, посмотреть план, очередь закрытия,
график, «если платить больше», экспорт. Не работает только то, что требует Telegram:
открытие мини-аппы и вход по коду — для этого нужен публичный HTTPS-адрес (домен или туннель).

Остановить: `Ctrl+C`.

## Запуск на своём компьютере (чтобы бот работал в Telegram)

Коротко: **сервер работает у вас, а Telegram ходит к нему через туннель**. Бот при этом
не требует публичного адреса вообще — он сам опрашивает Telegram (длинные запросы).
Внешний HTTPS-адрес нужен только мини-аппе, потому что её открывает клиент Telegram.

### Что понадобится

- Node.js 18 или новее;
- бот, созданный в [@BotFather](https://t.me/botfather);
- интернет (для туннеля).

### Шаг 1. Настройки

Скопируйте `.env.example` в `.env` и заполните:

```ini
TELEGRAM_BOT_TOKEN=123456:AA...      # выдаёт @BotFather при /newbot
TELEGRAM_BOT_USERNAME=my_debtfree_bot  # имя бота без @ — нужно для входа в браузере
PORT=8080
```

Файл `.env` в git не попадает: токен остаётся только у вас.

### Шаг 2. Запустить сервер

```bash
npm start
```

На Windows удобнее двойным кликом по **`start.cmd`** — он то же самое и не даст
забыть, что окно надо оставить открытым. Сервер скажет, в каком он режиме:

```
DebtFree: http://localhost:8080  — боевой режим (проверка подписи Telegram)
  настройки: .env (TELEGRAM_BOT_TOKEN, TELEGRAM_BOT_USERNAME, PORT)
Бот: @my_debtfree_bot
```

Проверьте, что приложение открывается локально: <http://localhost:8080>

### Шаг 3. Поднять туннель (второе окно)

```bash
node tools/tunnel.js
```

На Windows — двойной клик по **`start-tunnel.cmd`**.

Скрипт сделает всё сам:

1. запустит туннель к вашему порту и дождётся внешнего адреса;
2. снимет вебхук (боту он не нужен);
3. пропишет адрес в бота — кнопка меню в чате и главная мини-аппа.

В конце он напишет что-то вроде:

```
✓ Публичный адрес: https://fast-cat-42.loca.lt
Бот: @my_debtfree_bot (DebtFree)
Кнопка меню → https://fast-cat-42.loca.lt

Бот настроен: кнопка меню ведёт на https://fast-cat-42.loca.lt
Откройте https://t.me/my_debtfree_bot и нажмите кнопку меню.
```

Откройте бота в Telegram, нажмите кнопку меню слева внизу — приложение откроется.

### Итог: два окна

| Окно | Что запущено | Если закрыть |
|---|---|---|
| 1 | `npm start` (или `start.cmd`) — сервер | приложение перестанет работать |
| 2 | `node tools/tunnel.js` (или `start-tunnel.cmd`) — туннель | Telegram не сможет достучаться |

Компьютер должен быть включён, пока вы пользуетесь приложением. Остановить — `Ctrl+C`
в каждом окне.

### Про адрес туннеля

Бесплатный туннель выдаёт **новый адрес при каждом запуске**. Это не проблема: скрипт
каждый раз прописывает новый адрес в бота сам. Нужно только после перезапуска снова
запустить `tunnel.js` (или `start-tunnel.cmd`).

Если хочется постоянный адрес — варианты:

- **`cloudflared`** — `node tools/tunnel.js --provider=cloudflared` (умеет именованные туннели к своему домену);
- **`ngrok`** — `node tools/tunnel.js --provider=ngrok` (постоянный домен в платном тарифе);
- **свой VPS с доменом** — тогда туннель не нужен вовсе: сервер работает там, а домен
  прописывается в бота один раз.

Посмотреть адрес, не настраивая бота: `node tools/tunnel.js --no-setup`.
Прописать адрес вручную: `node tools/setup-bot.js https://ваш-адрес`.
Убрать кнопку меню: `node tools/setup-bot.js --clear`.

### Если на Windows ругается на npx

PowerShell может запретить запуск `npx` («выполнение сценариев отключено в этой системе»).
Это политика Windows, а не проблема проекта. Два решения:

1. запускать через `start.cmd` / `start-tunnel.cmd` — они вызывают `cmd.exe` и обходят запрет;
2. разрешить скрипты для текущего пользователя (один раз):

   ```powershell
   Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
   ```

### Если что-то не работает

| Симптом | Причина и что делать |
|---|---|
| «Telegram требует HTTPS и обычный домен» | провайдер туннеля не подошёл: `node tools/tunnel.js --provider=cloudflared` |
| Кнопки меню нет в чате с ботом | адрес не прописан: `node tools/setup-bot.js https://ваш-адрес` |
| После перезапуска приложение не открывается | туннель нужно запустить заново — адрес сменился |
| Браузер не пускает по коду | не задан `TELEGRAM_BOT_USERNAME` в `.env` |
| «Не удалось загрузить данные» | сервер не запущен или туннель закрыт |

## Запуск на сервере (постоянная работа)

Когда есть VPS и домен — это основной способ: сервис работает на сервере, nginx или
Caddy отдаёт его по HTTPS, туннель не нужен. Готовые файлы и пошаговая инструкция:

- **DEPLOY.md** — полный гайд: DNS, Node.js, systemd, Caddy или nginx+certbot, настройка бота;
- `systemd/debtfree.service` — служба для автозапуска;
- `deploy/Caddyfile` и `deploy/nginx.conf` — готовые конфиги прокси.

Если коротко:

1. выложить `debtfree/` на VPS (в `/opt/debtfree`), заполнить `.env` (токен, имя бота, `PUBLIC_URL=https://ваш-домен`);
2. включить службу: `sudo systemctl enable --now debtfree`;
3. поставить Caddy или nginx+certbot и направить домен на `127.0.0.1:8080`;
4. один раз прописать адрес боту: `node tools/setup-bot.js https://ваш-домен`.

Резервная копия — `data/store.json`; cron-копия раз в сутки описана в DEPLOY.md.

Скрипты туннеля (`tools/tunnel.js`, `start-tunnel.cmd`) нужны только для пробы на
домашнем компьютере без домена — с VPS они не используются.


## Как входить в браузере

Пароля нигде нет — и это не упрощение, а следствие того, что личность подтверждает
Telegram, а не браузер:

1. Откройте адрес сервера в браузере — увидите экран входа.
2. Нажмите «Войти через Telegram»: появится код и кнопка на бота.
3. Откройте бота и подтвердите вход (кнопкой или командой `/start КОД`).
4. Браузер сам заметит подтверждение и откроет ваши данные.

Код одноразовый и живёт 10 минут, сессия — месяц. В браузере она хранится в куке
`HttpOnly` и `SameSite`, то есть недоступна скриптам и не уходит на другие сайты.
Выйти можно кнопкой «Выйти» в разделе «Ещё».

## Автономный файл

Собрать заново (он же пересобирается автоматически при старте сервера, если исходники новее):

```bash
npm run build
```

Появятся:

- `../debtfree.html` — файл для отправки в мессенджере, работает двойным кликом;
- `public/debtfree.html` — та же сборка, отдаётся сервером по адресу `/debtfree.html`,
  её можно скачать из раздела «Ещё».

Файл умеет то же, что сервис, но по-своему хранит данные: если сервер рядом есть,
он подключится к нему; если нет — посчитает сам и сохранит в браузере, с экспортом
и импортом JSON.

## Структура

```
debtfree/
├─ src/
│  ├─ calc.js      расчётное ядро: чистый JS, один для клиента, сервера и файла
│  ├─ auth.js      проверка подписи Telegram + веб-сессии
│  ├─ bot.js       бот: подтверждение входа, дальше — напоминания
│  └─ server.js    HTTP-сервер: страницы, API, статика
├─ templates/      источник интерфейса: app.html и style.css
├─ public/         то, что отдаётся браузеру (собирается из templates)
├─ tools/build.js  сборка страницы сервиса и автономного файла
├─ tests/          243 проверки: ядро, подпись, сессии, файл, сервер
└─ data/           данные пользователей (создаётся при запуске, в git не попадает)
```

## API

Всё, кроме `health` и маршрутов входа, требует подтверждения личности — подписью
Telegram (`Authorization: tma <initData>`) или сессионной кукой.

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/health` | состояние сервера |
| GET | `/api/auth` | режим работы, доступен ли вход в браузере, имя бота |
| POST | `/api/auth/login/start` | создать код для входа в браузере |
| POST | `/api/auth/login/check` | забрать подтверждённый код и получить куку |
| POST | `/api/auth/logout` | выйти |
| GET | `/api/me` | профиль, условия, свои долги |
| GET | `/api/plan` | очередь закрытия, срок, проценты, экономия, календарь, «если больше» |
| POST | `/api/debts` | сохранить свои долги |
| POST | `/api/profile` | сохранить бюджет, стратегию, разовую доплату |
| DELETE | `/api/data` | удалить все свои данные |

## Тесты

```bash
npm test                  # все наборы подряд
node tests/calc.test.js       # ядро: сверка с независимой моделью
node tests/auth.test.js       # подпись Telegram (включая пример из документации)
node tests/session.test.js    # веб-сессии: одноразовость, сроки, изоляция
node tests/standalone.test.js # автономный файл: работает без сервера
node tests/server.test.js     # сервер: API, изоляция данных, раздача файлов
```

Что именно проверяется важного:

- **ядро** сверяется с отдельно написанной моделью — расхождение хотя бы на рубль
  валит тест;
- **подпись** проверяется на примере из официальной документации Bot API, а не сама на себе;
- **изоляция**: два пользователя не видят долгов друг друга ни через один маршрут;
- **веб-вход**: правка, сделанная в браузере, видна в Telegram, а после выхода доступ
  закрывается;
- **раздача файлов**: серверный код наружу не уходит, обход путей не работает.

## Приватность и ограничения

- **Вход без пароля.** Личность подтверждает Telegram: в мини-аппе — подписью,
  в браузере — одноразовым кодом. Подпись старше суток не принимается.
- **Что хранится:** имя и username из Telegram, список долгов, бюджет, стратегия.
  Никаких платёжных данных, доступов к банкам и документов.
- **Удаление:** кнопка «Удалить все мои данные» стирает долги и настройки.
- **Точность расчёта:** проценты считаются как «остаток × ставка / 12»; банки
  начисляют по фактическим дням, поэтому итог может отличаться на небольшую сумму.
- DebtFree — не финансовая рекомендация и не заменяет договор с банком.
